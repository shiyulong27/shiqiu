## 最小数据约定

采用现有 ESM JS 数据模块，不新增框架、数据库或依赖。

| 对象 | 必填字段 | 条件/可选字段 |
|---|---|---|
| 章节 | id、title、intro、startEntryId | relatedPages |
| 条目 | id、chapterId、title、question、shortAnswer、explanation、example、scopeNote、claimKind、sourceIds、visualRefs、reviewStatus | aliases、keywords、scenarioTags、prerequisiteIds、relatedIds、misconceptions、compare、challenge |
| 来源 | id、title、publisher、url 或版本页码、accessedAt、readStatus、supports | author、publishedAt；未知日期使用 null，不推测 |
| 图解 | id、title、caption、alt、kind、data、provenance | 引用实物图片时必须有本地路径、原链接与授权记录 |
| 题目 | id、entryId、question、options、answerIndex、explanation | difficulty |

- `reviewStatus`：draft / verified / blocked。公开页面只展示 verified；禁止用默认值把新条目自动标记为已核验。
- `readStatus`：正文已读 / 索引正文已读 / 索引释义已读 / 仅线索 / 访问失败。索引读取只在实际取得支持结论的释义或正文内容时登记，并明确区别于直接打开原页；仅命中标题或片段不足以支持结论时仍保留线索状态。
- `claimKind`：现代事实 / 文献释义 / 传统观念 / 地方习俗 / 教学建议 / 混合。混合条目在解释与范围说明中区分各部分。
- `sourceIds` 仅绑定直接支持的释义或事实。自主设计的情境、观察任务与礼貌建议标为教学建议，不冒充古代记载；来源的 `supports` 指明事实边界。
- `compare` 是带标签的解释型对照表，可用于简单知识点；Emoji 不能充当图解。复杂关系使用单独的 VIS 图解。
- `challenge` 为一个问题和解释，不强制每条复杂选择题；正式答题题库引用 entryId，争议问题限定语境。
- 本期候选问题全部保留。共享关系图可多条引用，已有专题只复用经核验部分，不把来源链接本身当知识讲解。
