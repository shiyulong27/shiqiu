## 一、背景

2026-10-27，4321 被 Windows 划入排除端口范围，Astro 启动报 EACCES，因此临时改在 127.0.0.1:14321 启动，没有修改源代码。用户随后关闭了服务。10-28 用户发现新端口下答题记录不可见，希望融合旧端口和新端口记录。两端口使用同一个 Chrome，但当前可用浏览器工具只有 Codex 内置浏览器，不能直接检查用户 Chrome 的记录。

## 二、目的

让原 Chrome 中两个端口的成绩和错题本安全地合并到 4321（用户 08:54 明确的目标）；保留合并前数据和 14321 来源记录，并使用户能明确验证实际恢复数量。

## 三、方案

### 推荐方案

新增本地答题记录备份与合并页面。通过严格限定来源的只读 iframe 获取同一浏览器中来源端口 14321 的数据；预览记录数量后，先保存包含双方原始数据的备份，再把完全相同记录去重后的并集写入当前端口 4321。读取或校验失败时不写入；同 ID 但内容不同的记录保留。提供备份下载、粘贴导入、合并前本地快照与恢复入口。

### 方案步骤

1. 核实实际存储键、数据字段、浏览器访问边界和端口可用性。
2. 实现迁移入口与纯合并逻辑；保持旧端口只读。
3. 用针对性的单元测试验证去重、无损保留、并发检查、写入失败回滚与损坏数据拒绝。
4. 启动两个端口，在可访问浏览器核实空数据与错误路径；由原 Chrome 读取和合并真实数据。

### 备选方案与取舍

- 若旧端口无法启动或主机名不同，改为在旧地址导出、当前地址导入；不修改系统端口保留配置。
- 不直接编辑 Chrome 的磁盘数据库；避免浏览器锁、配置文件混淆和覆盖风险。

## 四、成功标准

- 合并前保存双方原始字符串备份，来源端口 14321 数据保持不变。
- 完全相同记录只保留一份，内容不同的作答全部保留；重复合并不增加数据。
- 读取失败、非法备份、并发变化和写入失败均可观察，不静默当作空记录覆盖。
